Hierdoor merkte ik dat een technische planning niet alleen uit losse taken moet bestaan. Het is ook belangrijk om rekening te houden met de volgorde waarin componenten worden ontwikkeld en met de afhankelijkheden tussen deze onderdelen.

## Welke inzichten wil ik voor een volgend project behouden?

Er zijn verschillende technieken en inzichten die ik bij een volgend project opnieuw wil gebruiken:

* **Efficiënte image caching:** Ik heb geleerd hoe ik een optioneel icoontje kan renderen en persisten kan opslaan binnen mijn Android applicatie. Als de gebruiker in hun Gallerij de afbeelding verwijdert is deze nog beschikbaar in de App.
* **SQL relationele tabellen en Excel-exports:** Ik heb geleerd hoe ik relationele tabellen vanuit SQL kan exporteren naar een locatie op het android device
* **Provider states:** Door te leren over provider states is de clutter omtrend component pipelines enorm vermindert.

## Welke inzichten ga ik bij een volgend project aanpassen?

Bij een volgend project wil ik mezelf meer tijd geven om onderdelen volledig uit te werken. Ik wil voorkomen dat ik te veel onderdelen tegelijk probeer te verbeteren terwijl de basisfunctionaliteiten nog niet allemaal klaar zijn.

Daarnaast wil ik eerder bepalen wanneer een functionaliteit "goed genoeg" is. Hierdoor kan ik voorkomen dat ik onnodig veel tijd besteed aan kleine verbeteringen en daardoor belangrijke onderdelen van het project niet af krijg.
